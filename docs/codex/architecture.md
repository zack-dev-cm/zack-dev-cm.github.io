# Architecture

Use this file to preserve the boundaries that keep the portfolio maintainable and safe to publish.

## Domains

- Portfolio UI: `App.tsx`, `components/`, and CSS classes in the React shell.
- Portfolio data: `constants.ts` and `types.ts`; project facts should live here first.
- Project search: `utils/project-search.mjs` owns text indexing, query matching and ordering. `App.tsx` owns filters, query state and keyboard handoff. Relevance tests use the same reviewed catalogue and search module as the website.
- Generated public artifacts: `projects/`, `llms.txt`, `llms-full.txt`, `agent-context.md`, `geo.txt`, `schema.jsonld`, `sitemap.xml`, and matching `docs/` copies.
- Resume surface: `public/resume/` source files plus generated `docs/resume/` copies.
- Deployment output: `docs/`, generated by Vite and postbuild scripts.
- Agent knowledge: `codex-docs/` source copied into `docs/codex/` after each build.

## Guardrails

- Source changes should flow through generation scripts instead of hand-editing generated project pages.
- Public metrics need source context, dates, and careful wording that avoids user-count claims unless usage is directly supported by the source.
- Same-site GitHub Pages links should resolve locally in link checks before deployment.
- Resume claims must be ATS-readable and consistent with portfolio claims.
- Public-surface files must not include local paths, local URLs, secrets, or private operational notes.

## Do-not-break list

- `SOCIAL_LINKS` drives LinkedIn, GitHub, email, Telegram, and resume routes.
- `PROJECTS` IDs and generated slugs are used for share URLs and crawlable project pages.
- `LATEST_UPDATES` links must stay valid after `scripts/generate-project-markdown.mjs`.
- `docs/` is GitHub Pages output and is rebuilt by `npm run build`.
- The ClawHub download section must present downloads as public listing counters, not customer usage.
